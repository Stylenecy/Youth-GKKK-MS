harden: move Cross-leadership writes to SQL-enforced RPCs, no rush this time

Dex called off tonight's rollout after ibadah — nobody but Angel knows this
exists yet. With the time pressure gone, this closes the gap the rushed
version had documented and accepted rather than fixed: any signed-in user
could call the Supabase REST API directly and self-insert as leader of any
group, because the shared claim code was only checked in the Next.js
server action, never in Postgres. Someone bypassing the app entirely
wouldn't have needed the code at all.

Migration 0004 moves both writes (claim leadership, add a member) into
SECURITY DEFINER functions — claim_cross_leadership() and
add_cross_member() — that validate the code and the caller's leadership
in SQL, in one transaction each. The permissive INSERT policies from 0003
are dropped: cross_memberships and profiles now accept no direct client
writes at all, only through these two functions. A partial unique index
closes the same-second double-claim race that a check-then-insert alone
can't.

ADMIN_EMAILS and CROSS_CLAIM_CODE move out of Vercel env vars into two
locked-down tables (admin_emails, cross_claim_codes — RLS enabled, zero
client policies, readable only by the functions above or the SQL Editor).
One source of truth instead of two, and Dex can rotate the code himself
without redeploying or asking me. Both env vars removed from Vercel.

Also, since there was room to do this properly instead of just fast:

- get_my_app_role() RPC replaces the env-var admin check in
  getCurrentProfile() — same reasoning, one source of truth.
- /dashboard/cross/mine now matches what the backend actually allows: an
  admin can add members to any group (already true in the RPC), so the UI
  now shows every group to an admin, labeled clearly when it's "managing
  via admin access" versus a group they've personally claimed as CL.
- Quick-add warns (not blocks) on a name that already exists in the group
  — a mistyped duplicate is more likely than two people who happen to
  share a nickname, but it does happen, so this doesn't hard-block it.
- Empty states rewritten to guide rather than state absence: an unclaimed
  group says how to claim it, a claimed-but-empty group says one name is
  enough to start, /dashboard/members no longer tells people to run a
  seed.sql that no longer describes how member data actually gets in.
- Verified no hardcoded assumption of "8 leaders" or "5 claimed groups"
  anywhere — every group renders from its own membership rows, so the
  Dex+Angel pilot (1-2 claimed groups) and a full rollout render through
  the same code path.
- Test suite: 36 -> 50. New: tests/validation.test.ts (the name rule
  mirrored client-side) and tests/cross-data.test.ts (every demo-mode
  data.ts helper this feature added, including the session-aware ones
  failing safe to null/[] outside a real login instead of throwing).

PROJECT_MASTER.md now carries a calm, no-deadline setup guide for the one
remaining step (enabling Google as an Auth provider — needs Dex's own
Google Cloud Console access, which no tool here can reach) with a time
estimate and a 30-second way to verify it worked.

Verified: tsc clean, 50/50 tests, production build clean, migration 0004
applied via Supabase MCP and confirmed by querying the database (4
functions exist, admin_emails/cross_claim_codes seeded, the old insert
policies are gone) rather than assumed successful.

The 7 Aug session replaced the landing hero with a Three.js canvas and
repointed the demo seed at the real GKKK Yogyakarta roster. Neither change
was committed or deployed, so production was never affected.

Three regressions, restored here:

1. Real member data reached a public surface. seed.ts was rewritten with
   twelve real full legal names and exact birth dates taken from the
   WhatsApp export in .agent/ — the directory .vercelignore excludes from
   deploys precisely because it holds personal data. Everything in src/
   ships, and while Supabase is unconfigured proxy.ts lets every
   /dashboard request through without a login, so /dashboard/members would
   have published those names and birth dates to anyone with the URL.
   Whether real names appear publicly is still Dex's open decision.
   The seed is demo data again; the real roster is preserved under
   database/, which never leaves this machine.

2. Demo dates were pinned to 2026-08-08 and the comment explaining why
   that is a bug was deleted. getUpcomingGathering() filters out past
   events, so the landing headline would have changed by itself at 17:00
   that day and the whole site would have fallen back to its empty state
   after 29 Aug. Restored to dates computed relative to today.

3. Three.js added 561 KB raw / 139 KB gzip to the landing page as a hard,
   non-lazy import — the one page every jemaat opens, on mid-range phones.
   The canvas also ran an unconditional requestAnimationFrame loop with
   bloom and a mirror pass, ignoring prefers-reduced-motion entirely, had
   no WebGL fallback, and leaked its LFO oscillators and GPU buffers on
   unmount. Client JS is back to 197 KB gzip, down 41%.

The component and its write-up are kept verbatim under docs/experiments/
rather than discarded; the technique is worth reusing where a heavy canvas
belongs. Useful content it introduced is kept: Ruang Hermon as the venue,
the Saturday 15:00 latihan, and the five-group Cross structure.

Also carried forward, previously unfinished:

- Edit and delete for events and finance rows. Both are soft: events
  archive, transactions set deleted_at (migration 0002), matching the
  site's promise that the next kepengurusan inherits a memory rather than
  an empty folder. Both are reversible.
- Per-Cross member rosters, via the cross_memberships table that already
  existed in the schema but was never wired up. Counts now come from the
  membership rows instead of a memberCount column that drifts.
- Event times. A bare <input type="date"> was saved as UTC midnight, i.e.
  07:00 WIB, which would have silently moved every 17:00 service. Forms
  now take a WIB time and wibToISO() converts it explicitly.
- First test suite: 35 tests over WIB formatting, seed invariants,
  membership integrity and schema validation. One test fails the build if
  a real name from the archived roster reappears in seed.ts; another fails
  if seed dates are ever pinned to a literal calendar date again.

Verified: tsc clean, 35/35 tests pass, 12 routes 200 locally, one h1 per
page, 0 WCAG AA failures across all 14 colour token pairs.
